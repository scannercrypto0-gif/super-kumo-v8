## Actual implementation and evidence truth

`aql_r5b_public_pilot.py` creates a newly empty evidence directory and isolated
DurableJournal/OperationalStore DBs only. The actual BinanceCollector constructor
calls original register_legacy_writer. It is rechecked before the socket; v2
reserved/activated authority rejects instead of being disabled or bypassed.
No existing pipeline, Collector.run, startup/disconnect recovery or background
worker is started. After strict raw identity/finality/grid/OHLCV/time validation,
the adapter invokes **the actual Collector._on_message** and actual Journal
commit/commit_receipt. background_persistence prevents operational upsert; no
background thread is created. Collector errors cannot silently become success.

An immutable engineering C2 BASE/SHADOW schedule is fsynced/read back **before
network/provider/message receipt**. Future source-content hash is null, not a
fabricated hash of a locator or schedule. It is explicitly an engineering
schedule with MISSING_CAPTURE arms, NOT an original authenticated G2 event.
Original exact WS **application payload** bytes (not TLS packets or WS frame
headers) are stored base64 in an append/fsync hash-chain transcript with local
UTC/monotonic receipt time. Each committed final raw hash/sequence is linked to
actual stable key, checksum and persisted v1 commit-return receipt. Recomputed
raw-to-MarketBar checksum must match actual stored journal content. Unknown
source correction history and external publication/clock/custody stay unknown.
Nonfinal messages never commit. Malformed/late/future/duplicate/wrong-source
finals, schedule drift, resource cap, EOF, egress failure and deadline terminate
without retry. No raw input is claimed to be source-live by offline tests.

`eligible_prefix` reads only actual final, checksum-valid, integrity-eligible
BTCUSDT15m journal bars whose **ingest AND commit-return receipt** are <=cutoff;
requires continuity, no future receipt/lookahead. Existing R4 requires21 bars
and a fully bound schedule. A fresh one-bar pilot cannot provide that warmup:
it emits **SOURCE_PREFIX_INSUFFICIENT**, NOT_EVALUATED per arm and r4_invoked=false.
Moreover, a newly closed bar often arrives after its modeled bar-close cutoff;
that receipt is not backdated into R4 known-at eligibility. R4's exact last-bar
cutoff and source-known-at contract is not weakened to fabricate a call. A
ready fully bound source schedule/eligible prefix would require a separate
capability; this adapter explicitly refuses that unsupported branch. R4 and
Factory R3/R4 were source-inspected, not modified or retested. Factory currently
accepts fixture-only R4 schema; a source-engineering artifact must not be fed to
it as a genuine prospective F1. Minimal Factory delta follows only actual pilot
source delivery and its own scope.
