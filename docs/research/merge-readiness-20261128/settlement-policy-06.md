## Additive receipt protocol

`settlement.create_plan` reads the actual run identity and seals a create-only plan **before T**. T is fixed at started_ms + the planned86400seconds; eligible1m opens are [ceil(start/minute),floor(T/minute)). A bar closing exactly at T remains eligible; partial leading/trailing minutes are excluded without changing the denominator later. Both source/config/code/run and the plan are pinned. Past-run enrollment and runs that ended prematurely fail closed.

`capture_endpoint` creates a separate immutable endpoint receipt at T (bounded2000ms capture uncertainty, measured on wall and monotonic clocks). It records actual rows/lineage and complete bounded source events as of T. It never fabricates SERVICE_STOP or edits the original run timestamps/receipts. A missing boundary candle remains explicitly missing at the endpoint. This receipt captures bar coverage/event identity; it does **not** replace the separate existing market-freshness/operational observation verifier.

`finalize` reads source SQLite in query-only transactions and accepts delivery only for those predeclared eligible bars, at actual received_ms<=actual finish, with a hard inclusive T+120000ms deadline on **both** wall and monotonic clocks. Late rows retain their actual availability/lineage hashes. Independent source reopen rechecks the endpoint snapshot, exact source identity and all settlement rows via the existing `_verify_lineage` implementation, not a second weaker parser. Each eligible row also needs a same-run FINAL_BAR_RECEIVED event binding symbol/open/actual receive time; another session cannot settle this run. REST is not silently enabled: no RESTproducerpin is granted by this policy. Endpoint rewriting, missing/duplicate/conflicting rows, unverified lineage, clock anomalies, source rewrites and external pin mismatches fail closed. Other future bar opens cannot fill missing eligible slots. Original source remains read-only. Later conflicts or freshness must still be handled by the operational gate; this is a bounded as-of-finish coverage classification.

`acceptance_gates.evaluate_settlement_coverage` is the opt-in existing-gates entry point. It requires externally retained plan/endpoint/verifier-code pins, independently recomputes the final receipt, and returns SETTLEMENT_COVERAGE_PASS/BLOCKED. PASS exposes original coverage_at_endpoint, late_bars and settled_bars, and explicitly returns operational_24h_acceptance=NOT_ATTESTED, trading_authority=NONE. It does **not** turn the old endpoint's missing-bar result into an unqualified24h PASS, change its clocks or retroactively use post-T rotations/fault recovery. The original `evaluate_24h_report` remains strict and unchanged. Composition into any future host observation/market-freshness acceptance requires its separately authorized adapter and independent review; no automatic feed extension or host deployment is provided or claimed.

## Resource and custody bounds

At most10080eligible rows/events; five-second SQLite query progress deadline;8MB maximum canonical receipt; no directory recursion or provider calls. Larger workloads reject explicitly rather than scan/page silently. Output uses caller-selected separate paths with exclusive create, flush/fsync and no overwrite. Incomplete crash output fails canonical/hash verification; it is not an accepted receipt. No writable source connection, livehost scan, filesystem owner-authenticity or publisher-signature claim. Hash seals prove local integrity against externally retained pins, not hostile same-filesystem-owner custody.

## Continuation07 — independent Audit monotonic snapshot cutoff correction

[Audit7238141443](https://github.com/scannercrypto0-gif/super-kumo-v8/issues/134#issuecomment-7238141443) independently verified the prior121/85four-cell matrix but identified a static race: a row with wallreceived<=finish could have its matching commit's monotonic time after sampled finish/deadline, yet enter the SQLite snapshot before reading. This was a counterexample, not an observed host incident.

Every collect call now receives and records both wall and monotonic cutoffs, validates them against fixed plan/harddeadline, and constrains source events on both clocks inside the same read-only transaction. A row cannot qualify without its matching same-run commit in that bounded event set; a post-cutoff commit cannot support coverage even when its walltime passes the wallfilter and2sclockskew check. Final snapshot uses the exact sampled now/mono pair. Independent source recomputation uses those same recorded cutoffs, never currenttime or an expanded allowance.

Endpoint membership is explicitly wall<=T AND monotonic<=M_start+86400000, independently of the permitted2scapture uncertainty. Capture may happen later within its bounded window, but this never admits post-endpoint events into original endpoint coverage. A wall-eligible row with no eligible matching commit is rejected conservatively, not dropped to shrink the denominator. Existing immutable endpoint and plan remain protected; no fakeSERVICE_STOP, receipt rewrite or migration. Verifier code pin changes, so older sealed plans cannot silently enroll under changed verifierbytes.

Targeted deterministic regressions insert a real Store commit after finalizer clock sampling but before SQLite reading: one millisecond after an ordinary finish cutoff and after the120sdeadline, with walltime still in-bound. Both must reject. Endpoint test likewise rejects post-logical-monotonic-endpoint commits even within2scapturewindow. Positive exact-endpoint and existing exact-final-deadline cases remain inclusive. Twenty settlement cases total; no unrelated Core/scientific or host/provider rerun. Prior bounded acceptances retained; new correction requires independent delta judgment.
