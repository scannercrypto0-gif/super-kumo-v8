# H2 Official Binance Archive Lane — runnable opt-in implementation v1

**Status:** Implemented and focused CI tested on the existing Integration Draft PR #271. This is a *separate versioned opt-in* `OFFICIAL_BINANCE_ARCHIVE_NONCOMMERCIAL` lane alongside the unmodified default `strict-custodian` lane. Historical archive content matching does **not** establish download-time license, issuer PIT, publisher digital signature, commercial or economic approval. The owner-original E: experiment is **NOT** claimed executed.

## One Windows command (only after genuine private evidence exists)

The same pinned disposable-code Windows wrapper is used. The owner can select the official Binance lane explicitly:

```powershell
& '.\atlas_h2_windows_batch.ps1' -Mode official-binance -EvidenceDir '<EXISTING_PRIVATE_INTAKE_DIRECTORY>' -LicenseReviewerKey '<OUT_OF_BAND_RIGHTS_REVIEWER_VERIFIER_KEY>' -OwnerSigningKey '<SEPARATE_EXISTING_OWNER_LOCAL_KEY>' -ConfirmOneRun
```

By default the results and one SHA-sealed `h2-batch-summary.json` are written under Windows `LocalApplicationData\ATLAS\H2-Local-Batch\run-<unique>`. This wrapper creates and deletes only a disposable Git directory under `TEMP`, fetching pinned public code; it never checks out, cleans, resets or modifies the owner's 43 staged source files. No original market source is uploaded or included in CI/logs. Strict legacy users keep `-Mode strict-custodian` (the default) and original verified preexisting-custodian logic unchanged.

**Required pre-existing owner-private intake records** (in the one explicit `-EvidenceDir`, not GitHub/chat): `technical-intake.json` (schema `aql.integration.h2.official-binance-archive-intake.v1`), `historical-license-evidence.json` (schema `aql.integration.h2.historical-license-evidence.v1`), `historical-license-evidence.mac`, `historical-terms.txt` (exact rights terms bytes SHA-bound by licensed reviewer), `core245-native-receipt.json` (original retained whole-month Core245 native SHA chain) and `manual-third-ast.json` (existing real MANUAL strategy AST). The technical intake records existing Warehouse and RawVault roots, owner-local original ZIP location, official month, exact preexisting source/manifest/native/strategy file SHA/experiment identity and owner one-time permission `#205/6718325330`. These are existing local data-admission inputs, **never source-rights permissions on their own**. The owner should not manually fabricate JSON, historical terms, Core245 receipts, strategy hashes or signatures. If no genuine record/process exists, the correct result is one actionable `BLOCKED` report.

### Verification sequence (actual code)

1. **Official public publisher**: independently fetch a specific monthly Spot BTCUSDT/15m `ZIP` and its separate `.CHECKSUM` from fixed HTTPS `data.binance.vision` paths. No arbitrary URL or third-party redirect. Compare official filename-bound SHA-256, inspect ZIP member shape, full contiguous 15-minute CSV grid and *entire UTC calendar month* <=4096 bars. Reject modified or sparse source and archive reissue/identity drift. Evidence contains SHA/counts only, never raw public/owner bars.
2. **Rights before any E: source read**: independent license review for **the historical acquisition period (~2024)** and **personal noncommercial research** must be authenticated by a *pre-existing out-of-band rights-reviewer key* separate from the owner signing key. Its MAC verifies exact bytes of `historical-license-evidence.json` and the claimed terms SHA verifies the *retained actual* `historical-terms.txt` bytes. A purported JSON `INDEPENDENTLY_VERIFIED` status or string `signature_ref` is **not** itself independent authority; the owner must genuinely trust the externally verified reviewer/issuer. Current Binance Vision terms last updated 2026-08-26 must not silently be substituted for unknown 2024 terms. If terms/effective use or authenticator is unavailable, stop with `WAIT_LICENSE_*` and **do not read original source**. This verifier is NOT an invented historical custody HMAC and publisher `.CHECKSUM` is NOT license authorization.
3. **Original local content bridge only after rights + owner scope**: locate exactly the already specified original ZIP; verify its filename and **all bytes** SHA equals the independently downloaded publisher ZIP. Verify private Core245 retained native receipt SHA, contiguous complete month, dataset/version/source/manifest/cutoff against that source. The existing Core253 bounded immutable query runs only on the disposable SQLite snapshot after full owner confirmation and signed one-time scope; it MUST have its own distinct query SHA. Check original local ZIP SHA again after the engine returns.
4. **Single owner-approved run, unchanged existing engine**: automatically derive the precise signed operator scope using separately controlled owner-local key, explicit `-ConfirmOneRun`, exact Role commit SHA pins and exact seven Decimal bps (Spot LONG entry/exit fee 10/10, spread 2/2, slippage 3/3, funding 0). Reserve a one-time exclusive marker in private intake, not source. Existing WAL-aware read-only SQLite backup tolerates idle SHM / empty WAL and blocks nonempty WAL or durable original writes. Existing Scanner manual third AST → Factory generic results/replay and scientific Lab → Core Secretary durable WAIT (all four ACKs null) are reused, not reimplemented.
5. **One report**: `PASS_ENGINEERING_ONLY` **only after an actual owner-authorized complete local run and no-write check**. Otherwise one signed `BLOCKED` report naming the failing external evidence. When a prior run could have read original source before being blocked, source-read status says `POSSIBLE_AFTER_GATES`, never false `NOT_ATTEMPTED`. No PIT/known-at claim, statistical/economic endorsement, G0, PR merge, F5, Paper/live or trading.
